# AI-resources sync/skills setup — copy guide for print-service

Source: `certificate-service` (bksint), as of 2026-09-10.

This is the Gradle wiring that:
1. Checks out/updates the shared `.ai-resources` submodule and publishes its team
   instructions, skills, agents and git hooks — automatically, on every Gradle
   invocation and IDE import, and on every Claude Code session start.
2. Generates this repo's **own** skills (`.agents/skills/<name>/SKILL.md`) into the
   tool-specific locations Copilot CLI and Claude Code read.

**Scope note:** the certificate-workflow skills (`cert-scaffold`, `cert-category`,
`cert-pdf`, etc.) are certificate-service-specific and are **not** included here.
Copy only the mechanism below; print-service starts with an empty
`.agents/skills/` and can add its own skills later using the same script.

Everything generated by this mechanism is gitignored — only the 8 files/entries
below need to be added to print-service and committed.

---

## 0. Before you start — check what already exists

Applied to print-service on 2026-09-10; the target repo was not a clean slate, and this
guide originally assumed one. Check these before copying anything:

- **`.gitmodules` / the submodule may already be registered.** print-service already had
  the `[submodule ".ai-resources"]` block and a gitlink in the tree — don't assume a
  from-scratch `git submodule add`; run `git submodule status` first.
- **The submodule pin can be stale.** This is the change most likely to bite: a repo that
  registered the submodule before this bootstrap mechanism existed can be pinned to a
  commit that predates `bootstrap.sh`/`sync.sh` entirely (print-service was pinned to
  `810ef33`, "Fix sed in gitignore sync" — a commit with only the older git-hook-based sync,
  no `bootstrap.sh` at the submodule root). Check with:
  ```bash
  cd .ai-resources && git log -1 --oneline && git log origin/main -1 --oneline && cd ..
  ```
  If the current pin predates `bootstrap.sh`/`sync.sh` existing (compare against
  `c07bf88`, "Set the resources up automatically and publish to Claude Code as well" — the
  commit that introduced them), advance it first:
  ```bash
  cd .ai-resources && git checkout main && git pull origin main && cd ..
  git add .ai-resources   # stage the moved pin; commit alongside the rest of this setup
  ```
  Nothing else in this guide works until the pin is at or after that commit.
- **A previous partial attempt may have left a stale `.gitignore` block.** Look for an
  existing `# BEGIN ai-resources synced ... # END ai-resources synced` block (or similar)
  and replace it outright with section 8 below rather than merging — the entry set has
  changed since earlier iterations of this mechanism (it used to list one hardcoded skill
  path like `/.github/skills/caveman/`; it now lists the parent directories instead).
- **The generated files/dirs themselves are never hand-authored.** Once the submodule pin
  is current and the wiring below is in place, running the bootstrap publishes
  `.github/copilot-instructions.md`, `.github/skills/`, `.claude/skills/`, `.claude/agents/`
  automatically. Do not create or edit these yourself — only the 8 items below are
  hand-copied.
- **Current `.ai-resources` (as of `c07bf88`) manages its own gitignoring.** The submodule's
  `sync.sh` writes every path it publishes into the parent's `.git/info/exclude`
  (untracked, per-clone) rather than relying on the tracked `.gitignore`. The tracked
  `.gitignore` entries in section 8 below are still needed — they cover this repo's *own*
  local-skills output (`sync-local-skills.sh` does not self-manage `.git/info/exclude`) —
  but don't be surprised if `git status` already looks clean for the team-published paths
  even before you touch `.gitignore`.

## 2. `gradle/aiResources.gradle` (new file)

Runs the bootstrap script from `settings.gradle`, so it happens before anything
else — on every Gradle invocation and every IDE project import. Never fails the
build.

```groovy
import java.util.concurrent.TimeUnit

// Runs the AI resources bootstrap from settings.gradle, so it happens on an IDE project
// import and on every Gradle invocation — before anyone has been told to run anything.
//
// The work itself is in .github/scripts/ai-bootstrap.sh, shared with the Claude Code
// session-start hook. All this adds is a timeout and the guarantee that nothing here can
// fail configuration: a developer without access to the submodule, or a CI job that clones
// without submodules, still has to be able to build.
//
// Opt out with -PskipAiResources or SKIP_AI_RESOURCES=1.

def repoRoot = settings.rootDir
def bootstrapScriptPath = '.github/scripts/ai-bootstrap.sh'
def bootstrap = new File(repoRoot, bootstrapScriptPath)

def skip = settings.startParameter.projectProperties.containsKey('skipAiResources') ||
        System.getenv('SKIP_AI_RESOURCES')

if (!skip && bootstrap.exists() && new File(repoRoot, '.git').exists()) {
    try {
        def process = new ProcessBuilder(['bash', bootstrapScriptPath, '--quiet'])
                .directory(repoRoot)
                .redirectErrorStream(true)
                .start()
        if (process.waitFor(180, TimeUnit.SECONDS)) {
            def output = process.inputStream.text.trim()
            if (output) {
                println output
            }
        } else {
            process.destroyForcibly()
            println 'ai-resources: bootstrap timed out, continuing without it.'
        }
    } catch (Exception e) {
        // No bash (Windows without a shell), no permission — all the same to us.
        println "ai-resources: bootstrap could not run, continuing without it. ${e.message}"
    }
}
```

## 4. `.github/scripts/ai-bootstrap.sh` (new file, executable)

The entry point both Gradle and Claude Code call. Initialises the `.ai-resources`
submodule if missing, runs `.ai-resources/bootstrap.sh` (team layer), then runs
`sync-local-skills.sh` (this repo's own skills). Never fails.

```bash
#!/usr/bin/env bash
set -uo pipefail

# This repository's entry point for setting up the AI coding resources. Everything that
# knows how to do the work lives in the .ai-resources submodule; this is the thin part that
# has to be tracked here, because the submodule cannot initialise itself.
#
#   1. initialise .ai-resources if it is missing
#   2. .ai-resources/bootstrap.sh  — shared git hooks, team instructions, skills and agents
#   3. .github/scripts/sync-local-skills.sh — this repository's own skills
#
# Callers: gradle/aiResources.gradle (from settings.gradle, so every Gradle invocation and
# every IDE import) and .claude/settings.json (every Claude Code session start).
#
# It never fails. A developer without access to the submodule, or a CI job that clones
# without submodules, still has to be able to build; they lose the team layer and keep
# everything else.
#
# Usage:
#   .github/scripts/ai-bootstrap.sh [--quiet] [--force]

REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
cd "$REPO_ROOT" || exit 0

QUIET=0
FORWARD=()
for arg in "$@"; do
  case "$arg" in
    --quiet) QUIET=1; FORWARD+=("$arg") ;;
    --force) FORWARD+=("$arg") ;;
  esac
done

say() { [ "$QUIET" -eq 1 ] || echo "$@"; }

# Never stop to ask for credentials: an unexpected dialog on a developer machine, a build
# that hangs until the timeout on CI.
export GIT_TERMINAL_PROMPT=0
export GIT_ASKPASS=echo
export SSH_ASKPASS=echo

# Whatever started this build may have restricted git's transports — coding agents do, and
# a Gradle daemon keeps the environment of the client that started it long after that client
# is gone, for every later build in every checkout. GIT_ALLOW_PROTOCOL is an allowlist that
# overrides protocol.*.allow, so it has to be unset; a -c flag cannot outrank it.
unset GIT_ALLOW_PROTOCOL

SUBMODULE_PATH='.ai-resources'
SUBMODULE_URL_KEY="submodule.${SUBMODULE_PATH}.url"

# The transports we need, spelled out, so a restrictive protocol.*.allow inherited through
# GIT_CONFIG_PARAMETERS or a system config cannot stop us either.
git_submodule_update() {
  git -c protocol.https.allow=always -c protocol.ssh.allow=always \
      submodule update --init --recursive -- "$SUBMODULE_PATH" 2>&1
}

# .gitmodules records an HTTPS URL. Someone who cloned over SSH may have no HTTPS
# credentials at all, and GIT_TERMINAL_PROMPT=0 turns that into a silent failure. Rewrite
# the URL — in .git/config, never in the tracked .gitmodules — to the same Bitbucket project
# over the transport the superproject itself uses.
#
# A relative URL in .gitmodules cannot do this on Bitbucket Server: the HTTPS path carries a
# /scm prefix the SSH path does not, so no single relative path resolves for both.
#
#   ssh://git@host:7999/bksint/certificate-service.git -> ssh://git@host:7999/k1j/ai-resources.git
#   git@host:bksint/certificate-service.git            -> git@host:k1j/ai-resources.git
ssh_url_for_origin() {
  local origin="$1" module_url="$2" repo project dir
  case "$origin" in
    ssh://*|git+ssh://*) ;;
    *://*) return 1 ;;          # https, http, git, file
    *:*) ;;                     # scp-like, git@host:project/repo.git
    *) return 1 ;;
  esac

  repo="${module_url##*/}"                # ai-resources.git
  project="${module_url%/*}"; project="${project##*/}"   # k1j
  [ -n "$repo" ] && [ -n "$project" ] || return 1

  dir="${origin%/*}"                      # everything above the superproject's own name
  case "$dir" in
    */*) printf '%s/%s/%s\n' "${dir%/*}" "$project" "$repo" ;;
    *:*) printf '%s:%s/%s\n' "${dir%:*}" "$project" "$repo" ;;
    *) return 1 ;;
  esac
}

# One line saying what is actually wrong. The full git output is worth reading when this
# script is run by hand, but not in the middle of a build log.
report_failure() {
  local output="$1" reason
  case "$output" in
    *"could not read Username"*|*"Authentication failed"*|*"Invalid credentials"*)
      reason="no Bitbucket credentials — run: git submodule update --init" ;;
    *"not allowed"*)
      reason="git transports are restricted in this environment (GIT_ALLOW_PROTOCOL) — run ./gradlew --stop and build again" ;;
    *"Could not resolve host"*|*"unable to access"*|*"timed out"*|*"Connection refused"*)
      reason="Bitbucket unreachable (VPN?) — the next build will retry" ;;
    *"not our ref"*|*"did not contain"*)
      reason="the pinned .ai-resources commit is not on the remote — whoever moved the pin has to push it" ;;
    *)
      reason="$(printf '%s\n' "$output" | grep -E '^(fatal|error):' | tail -1)"
      [ -n "$reason" ] || reason="$(printf '%s\n' "$output" | grep -v '^[[:space:]]*$' | tail -1)" ;;
  esac
  echo "ai-resources: could not initialise the submodule, continuing without it." >&2
  echo "              ${reason}" >&2
  echo "              Shared instructions, skills, agents and git hooks are unavailable." >&2
  [ "$QUIET" -eq 1 ] || printf '%s\n' "$output" | sed 's/^/              /' >&2
}

if [ -f .gitmodules ] && grep -qF "$SUBMODULE_PATH" .gitmodules && [ ! -f "${SUBMODULE_PATH}/bootstrap.sh" ]; then
  say "ai-resources: submodule missing, initialising it..."

  module_url="$(git config -f .gitmodules --get "$SUBMODULE_URL_KEY" 2>/dev/null || true)"
  origin_url="$(git config --get remote.origin.url 2>/dev/null || true)"
  matched_url=""
  if [ -n "$module_url" ] && [ -n "$origin_url" ]; then
    matched_url="$(ssh_url_for_origin "$origin_url" "$module_url" || true)"
  fi

  # git submodule init leaves an already registered URL alone, so ours survives repeat runs.
  git submodule init -- "$SUBMODULE_PATH" >/dev/null 2>&1
  if [ -n "$matched_url" ] && [ "$matched_url" != "$module_url" ]; then
    git config --local "$SUBMODULE_URL_KEY" "$matched_url"
  fi

  if ! output="$(git_submodule_update)"; then
    # Whichever credentials the developer has, one of the two transports works: fall back to
    # the URL as tracked before giving up.
    if [ -n "$matched_url" ] && [ "$matched_url" != "$module_url" ]; then
      git config --local "$SUBMODULE_URL_KEY" "$module_url"
      output="$(git_submodule_update)" || report_failure "$output"
    else
      report_failure "$output"
    fi
  fi
fi

if [ -f .ai-resources/bootstrap.sh ]; then
  bash .ai-resources/bootstrap.sh "${FORWARD[@]:-}"
fi

if [ -f .github/scripts/sync-local-skills.sh ]; then
  if output="$(bash .github/scripts/sync-local-skills.sh 2>&1)"; then
    say "$output"
  else
    echo "ai-resources: local skill sync failed, continuing." >&2
    echo "$output" | sed 's/^/              /' >&2
  fi
fi

exit 0
```

Make it executable after copying: `chmod +x .github/scripts/ai-bootstrap.sh`.

## 5. `.github/scripts/sync-local-skills.sh` (new file, executable)

Generates print-service's own skills (once you add any under
`.agents/skills/<name>/SKILL.md`) into `.claude/skills/<name>/SKILL.md` and
`.github/agents/<name>.agent.md`. Refuses to overwrite a name the team submodule
already publishes.

```bash
#!/usr/bin/env bash
set -euo pipefail

# Generates the tool-specific copies of this repository's own agent skills.
#
#   source       .agents/skills/<name>/SKILL.md        tracked, edit this
#   Claude Code  .claude/skills/<name>/SKILL.md        generated, gitignored
#   Copilot CLI  .github/agents/<name>.agent.md        generated, gitignored
#
# This mirrors what .ai-resources/sync.sh does for team resources: one source, tool-specific
# copies, copies excluded from the repository. The difference is where the source lives —
# team skills come from the submodule, these are local to certificate-service because this
# is where certificate types are implemented.
#
# Both writers share .claude/skills/ and .github/agents/, so this script refuses to publish
# a name the team sync has already claimed rather than silently overwriting it.
#
# Runs automatically: gradle/aiResources.gradle calls it from settings.gradle, and `check`
# depends on it. Run it directly, or as `./gradlew syncLocalSkills`, to force it.
#
# Usage:
#   .github/scripts/sync-local-skills.sh [--check]
#
#   --check   verify the copies are current without writing; non-zero if stale.

REPO_ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
SRC="${REPO_ROOT}/.agents/skills"
CLAUDE_DST="${REPO_ROOT}/.claude/skills"
COPILOT_DST="${REPO_ROOT}/.github/agents"

CHECK_ONLY=0
if [ "${1:-}" = "--check" ]; then
  CHECK_ONLY=1
fi

if [ ! -d "$SRC" ]; then
  echo "local-skills: no ${SRC}, nothing to sync"
  exit 0
fi

# What the team sync published, if it has run in this clone.
TEAM_MANIFEST=""
if git -C "$REPO_ROOT" rev-parse --git-dir >/dev/null 2>&1; then
  git_dir="$(cd "$REPO_ROOT" && git rev-parse --git-dir)"
  case "$git_dir" in
    /*) ;;
    *) git_dir="${REPO_ROOT}/${git_dir}" ;;
  esac
  [ -f "${git_dir}/ai-resources-manifest" ] && TEAM_MANIFEST="${git_dir}/ai-resources-manifest"
fi

claimed_by_team() {
  [ -n "$TEAM_MANIFEST" ] || return 1
  grep -qxF -e "/.claude/skills/$1/" -e "/.github/agents/$1.agent.md" "$TEAM_MANIFEST"
}

stale=0
count=0

for skill_dir in "$SRC"/*/; do
  [ -d "$skill_dir" ] || continue
  name="$(basename "$skill_dir")"
  source_file="${skill_dir}SKILL.md"
  [ -f "$source_file" ] || continue

  if claimed_by_team "$name"; then
    echo "local-skills: ERROR - '${name}' is already published by the .ai-resources submodule."
    echo "              Rename .agents/skills/${name}, or drop it in favour of the shared one."
    exit 1
  fi

  claude_file="${CLAUDE_DST}/${name}/SKILL.md"
  copilot_file="${COPILOT_DST}/${name}.agent.md"

  if [ "$CHECK_ONLY" -eq 1 ]; then
    for generated in "$claude_file" "$copilot_file"; do
      if [ ! -f "$generated" ] || ! cmp -s "$source_file" "$generated"; then
        echo "local-skills: stale or missing -> ${generated#"${REPO_ROOT}/"}"
        stale=1
      fi
    done
  else
    mkdir -p "${CLAUDE_DST}/${name}" "$COPILOT_DST"
    cp "$source_file" "$claude_file"
    cp "$source_file" "$copilot_file"
  fi

  count=$((count + 1))
done

if [ "$CHECK_ONLY" -eq 1 ]; then
  if [ "$stale" -eq 1 ]; then
    echo ""
    echo "Run .github/scripts/sync-local-skills.sh (or ./gradlew syncLocalSkills)."
    exit 1
  fi
  echo "local-skills: ${count} skills up to date"
  exit 0
fi

echo "local-skills: synced ${count} skills -> .claude/skills and .github/agents"
```

Make it executable after copying: `chmod +x .github/scripts/sync-local-skills.sh`.

## 6. `build.gradle` — tasks block to add

Append near the end of `build.gradle` (adjust `rootProject` usage as needed if
print-service's root project differs):

```groovy
// This repository's own agent skills are authored once under .agents/skills/ and copied
// to the locations each tool reads. The copies are generated and gitignored, matching how
// .ai-resources publishes team resources. Because they are gitignored they are absent from
// any clean checkout, so `check` regenerates them instead of verifying them - verifying
// would always fail on CI. checkLocalSkills stays available for spotting drift by hand.
//
// These tasks are a backstop. gradle/aiResources.gradle already does all of this from
// settings.gradle, but settings scripts are skipped on a configuration-cache hit, so the
// wiring into `check` is what guarantees it still happens.

def aiResourcesBootstrap = '.ai-resources/bootstrap.sh'
def localSkillsScript = '.github/scripts/sync-local-skills.sh'
def localSkillsSource = rootProject.file('.agents/skills')

def localSkillNames = localSkillsSource.exists()
        ? localSkillsSource.listFiles({ File f -> f.isDirectory() && new File(f, 'SKILL.md').isFile() } as FileFilter)
        .collect { it.name }.sort()
        : []

tasks.register('syncLocalSkills', Exec) {
    group = 'ai tooling'
    description = 'Generates .claude/skills and .github/agents from .agents/skills.'
    // The public mirror is published from .github-publish-allowlist, which carries neither
    // .github/ nor .agents/, so there the script does not exist and `check` must still pass.
    onlyIf { rootProject.file(localSkillsScript).exists() }

    // .optional() only allows the property to be null - it does not skip the file-exists
    // check for a File that is set, so a not-yet-created .agents/skills/ (the normal state
    // for a repo with no local skills yet, e.g. a fresh print-service) fails task
    // validation ("Input file does not exist") unless guarded here.
    if (localSkillsSource.exists()) {
        inputs.dir(localSkillsSource).withPropertyName('sources')
    }
    // Only the files this task owns. The team sync writes other names into the same two
    // directories, so declaring the directories themselves would make the two fight.
    outputs.files(localSkillNames.collect { rootProject.file(".claude/skills/${it}/SKILL.md") })
            .withPropertyName('claudeSkills')
    outputs.files(localSkillNames.collect { rootProject.file(".github/agents/${it}.agent.md") })
            .withPropertyName('copilotAgents')

    workingDir rootProject.projectDir
    commandLine 'bash', localSkillsScript
}

tasks.register('checkLocalSkills', Exec) {
    group = 'ai tooling'
    description = 'Fails if a generated skill copy is missing or out of date.'

    workingDir rootProject.projectDir
    commandLine 'bash', localSkillsScript, '--check'
}

tasks.register('syncAiResources', Exec) {
    group = 'ai tooling'
    description = 'Publishes the shared .ai-resources instructions, skills and agents.'
    onlyIf { rootProject.file(aiResourcesBootstrap).exists() }
    ignoreExitValue = true

    workingDir rootProject.projectDir
    commandLine 'bash', aiResourcesBootstrap, '--quiet'
}

tasks.register('aiResourcesStatus') {
    group = 'ai tooling'
    description = 'Reports which AI resources are installed and which are missing.'

    doLast {
        def report = { String label, File f ->
            println "  ${f.exists() ? 'ok     ' : 'MISSING'}  ${label}"
        }
        println ''
        println 'Shared, from the .ai-resources submodule:'
        report('submodule checked out', rootProject.file('.ai-resources/bootstrap.sh'))
        report('.github/copilot-instructions.md', rootProject.file('.github/copilot-instructions.md'))
        report('.github/skills/', rootProject.file('.github/skills'))
        report('.claude/skills/caveman/SKILL.md', rootProject.file('.claude/skills/caveman/SKILL.md'))
        report('.claude/agents/', rootProject.file('.claude/agents'))

        def hooksPath = providers.exec {
            commandLine 'git', 'config', '--local', '--get', 'core.hooksPath'
            it.ignoreExitValue = true
        }.standardOutput.asText.get().trim()
        println "  ${hooksPath == '.ai-resources/hooks/git' ? 'ok     ' : 'MISSING'}  git hooks (core.hooksPath=${hooksPath ?: 'unset'})"

        println ''
        println "This repository's own skills:"
        localSkillNames.each { name ->
            report(".claude/skills/${name}/SKILL.md", rootProject.file(".claude/skills/${name}/SKILL.md"))
            report(".github/agents/${name}.agent.md", rootProject.file(".github/agents/${name}.agent.md"))
        }

        println ''
        println 'Anything missing is repaired by ./gradlew syncAiResources syncLocalSkills'
        println '(or .ai-resources/bootstrap.sh --force), which any build also does for you.'
        println ''
    }
}

tasks.named('check') { dependsOn 'syncAiResources', 'syncLocalSkills' }
```

If print-service is a multi-module build and this block is placed in the root
`build.gradle`, `rootProject` resolves correctly as-is.

## After copying: verification checklist

```bash
# 1. Register the submodule (if not already done via git submodule add above)
git submodule update --init --recursive

# 2. Confirm git hooks point at the submodule (bootstrap.sh sets this; run it once by hand
#    if you want to check before your first Gradle build)
bash .ai-resources/bootstrap.sh --force

# 3. Let Gradle wire everything and report status
./gradlew aiResourcesStatus

# 4. Confirm `check` picks up the new tasks
./gradlew check --dry-run | grep -E 'syncAiResources|syncLocalSkills'
```

`./gradlew aiResourcesStatus` should report the submodule checked out,
`.github/copilot-instructions.md` present, `.github/skills/` present, and git
hooks pointing at `.ai-resources/hooks/git`. The "This repository's own skills"
section will be empty until print-service adds anything under
`.agents/skills/`.

A benign message you'll see until the submodule pin bump (section 0) is actually
committed: `ai-resources: submodule is at <new-sha> but this branch records <old-sha>.
Leaving your checkout alone; it has local work.` This is `bootstrap.sh` reporting that
your working tree is ahead of the committed gitlink — expected mid-setup, harmless, and
it still publishes correctly. It goes away once the `.ai-resources` bump is committed.

## What was intentionally left out

- `.agents/skills/cert-*` (certificate-workflow skills) — certificate-service
  specific, not applicable to print-service.
- Any print-service-specific content in `AGENTS.md` / `.github/copilot-instructions.local.md`
  — those describe certificate-service's own conventions and would need to be
  authored fresh for print-service, not copied.
- `.github-publish-allowlist` (a print-service-specific public-mirror allowlist not present
  in certificate-service) — left untouched; `.claude/` and `.github/scripts/` were not
  added to it, by explicit choice, since they are outside this guide's scope.
